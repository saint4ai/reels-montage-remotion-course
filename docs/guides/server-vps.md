# Сервер (VPS) для ассистента

Проверено по документации и сайтам провайдеров 10.10.2026. Цены меняются, перед оплатой сверь их на сайте.

## Что это и зачем

VPS (виртуальный сервер) это маленький компьютер в дата-центре, который работает круглые сутки и всегда включён. Ты арендуешь его за деньги помесячно.

Зачем он тебе: ассистент должен принимать сообщения от Zernio в любое время, даже когда твой компьютер выключен. Zernio отправляет каждое новое сообщение на адрес твоего сервера (вебхук) и ждёт ответа в течение 5 секунд. Ноутбук для этого не годится.

Агент Claude Code сам заходит на сервер по SSH (защищённый удалённый вход) и всё там ставит: Docker, а в нём ассистента (программа на Python, база SQLite лежит внутри, отдельную базу данных заказывать не нужно) и Caddy для HTTPS. Тебе нужно только создать сервер и передать агенту доступ.

## Что понадобится

Минимальные параметры для Docker, ассистента и Caddy:

| Параметр | Минимум |
|---|---|
| Процессор | 1 или 2 ядра (vCPU), лучше 2 |
| Память | 2 ГБ |
| Диск | 20 ГБ и больше (SSD или NVMe) |
| Система | Ubuntu 24.04 LTS (если нет, подойдёт 22.04 LTS) |
| Адрес | публичный IPv4-адрес (один на сервер) |

Ещё нужно:

- Карта, которой можно оплатить выбранного провайдера (см. таблицу).
- Электронная почта и телефон для регистрации.
- Windows 10 версии 1809 или новее (в ней уже есть программа `ssh`) или macOS.
- Папка `Загрузки` для временного файла с доступами.
- Домен не обязателен (см. шаг 7).

## Шаги

### 1. Зарегистрируйся у провайдера

**Timeweb Cloud.** Открой https://timeweb.cloud, зарегистрируйся по почте. Пополни баланс: «Баланс и платежи» → «Оплата». Минимальный платёж 2 000 ₽. Серверы оплачиваются почасовыми списаниями с баланса. Выключенный сервер тоже оплачивается, пока он существует.

**Hoster.kz.** Открой https://hoster.kz и нажми «Регистрация». Выбери «Физическое лицо» (или «Юридическое лицо/ИП»), заполни данные, поставь галочку согласия с офертой, нажми «Регистрация». Логин и пароль придут на почту.

**Beget.** Открой https://beget.com, зарегистрируйся и пополни баланс в разделе «Оплата».

### 2. Пусть агент создаст SSH-ключ

SSH-ключ это пара файлов: **приватный** (секретный, остаётся на твоём компьютере) и **публичный** (его можно показывать и вставлять в панель). По ключу агент заходит на сервер без пароля.

Вставить публичный ключ при создании сервера можно, как подтверждено документацией, только в **Timeweb Cloud**. У Hoster.kz и Beget такого шага в справке нет. Для них ниже путь через пароль root: агент заходит по нему один раз и сам добавляет ключ.

1. Скажи агенту: «Создай SSH-ключ для сервера и покажи мне только публичную часть».
2. Агент выполнит в PowerShell команду `ssh-keygen -t ed25519`. Ключи появятся в папке `C:\Users\<твоё имя>\.ssh\`. Файл `id_ed25519.pub` публичный, файл `id_ed25519` приватный. (Если не указать тип, Windows OpenSSH тоже использует Ed25519.)
3. Агент покажет тебе содержимое файла с окончанием `.pub`. Это одна длинная строка, она начинается с `ssh-ed25519`.
4. Приватный файл (без `.pub`) никому не показывай, не отправляй и не вставляй в чат. Документация Microsoft прямо приравнивает его к паролю.

### 3. Создай сервер

**Пример: Timeweb Cloud** (шаги из справки timeweb.cloud/docs/cloud-servers/manage-servers/create-server).

1. Зайди в панель, раздел «Облачные серверы», нажми «Добавить» (или «Создать»).
2. Шаг «Программное обеспечение»: выбери чистую ОС Ubuntu, версию 24.04, если она есть.
3. Выбери регион (Казахстан или Москва, как тебе удобнее).
4. Выбери тариф: 2 vCPU, 2 ГБ, 40 ГБ или больше. Следи, чтобы на балансе хватало денег.
5. Раздел сети: «Публичный IPv4-адрес» → создать новый (он оплачивается отдельно).
6. Раздел «Авторизация»: нажми «Загрузить новый ключ», вставь публичный ключ из шага 2 (строку из файла `.pub`) и сохрани. После создания ключ окажется на сервере сам.
7. Переключатель «Доступ по SSH через root-пароль» выключает вход по паролю. Работает только если выбран SSH-ключ. Для новичка проще оставить его как есть, пока всё не заработает.
8. Дай серверу имя (например `assistant`) и нажми «Заказать».

**Пример: Hoster.kz** (справка hoster.kz/support/obshhie-voprosy/7050).

1. Вкладка «Облако» → «Облачные серверы».
2. Выбери тариф и нажми «Заказать».
3. Заполни: «Локация» (Алматы или Астана), «Имя сервера», «Срок заказа» (от 1 месяца до 3 лет), «Операционная система» (выбери Ubuntu).
4. «В корзину» → «Оформить заказ» → заполни платёжные данные → выбери способ оплаты. Услуга включится после оплаты.
5. В справке Hoster.kz не сказано, где взять IP-адрес и пароль сервера и можно ли сразу вставить SSH-ключ. Сервер создай с обычным паролем root (путь «ключ добавит агент» ниже) и спроси поддержку (support@hoster.kz), где в панели IP и пароль. Тестовый период на сайте упомянут («войдите в аккаунт или зарегистрируйтесь»), его срок на официальной странице не указан.

**Beget.** На странице VPS указано, что Ubuntu 24.04 есть и бесплатна, а сервер выдаётся с доступом root. Как передать SSH-ключ и где взять пароль, на этой странице не написано. Путь тот же, что у Hoster.kz: пароль root и добавление ключа агентом.

### 4. Найди IP-адрес и пароль root

- **Timeweb Cloud:** открой сервер, вкладка **«Дашборд»**, блок **«Реквизиты подключения»**: там IP-адрес, пользователь `root` и пароль. Пароль также показан на вкладке «Доступ». Там же есть готовая команда для SSH. Если пароля в панели нет, его могли отправить на почту. Нажми на значок замка или «Изменить» на вкладке «Доступ», чтобы задать новый пароль.
- **Hoster.kz и Beget:** смотри письмо на почту и раздел управления сервером. Если не нашёл, пиши в поддержку.

Если ты вставил SSH-ключ при создании (Timeweb Cloud), пароль root агенту не нужен. Но сохрани его для запасного входа.

### 5. Передай доступ агенту

IP-адрес секретом не является. Его можно написать в чат. А пароль root (если он нужен) нельзя: он идёт через файл `Загрузки\server-key.txt` по правилу ниже.

**Ключ вставлен в панели (Timeweb Cloud).**

1. Напиши агенту: «Адрес сервера такой-то (IP). Ключ SSH уже загружен. Зайди и проверь».
2. Агент выполняет `ssh root@<IP>`. Первый раз SSH спросит, доверять ли серверу. Агент подтверждает.
3. Если зайти не получилось, см. таблицу ошибок.

**Ключ вставить негде (Hoster.kz, Beget или не вставил).** Агент добавит его сам по паролю, один раз:

1. Сохрани пароль root в файл `Загрузки\server-key.txt` (правило ниже) и напиши агенту: «Адрес сервера такой-то (IP). Пароль root лежит в файле Загрузки\server-key.txt».
2. Агент читает файл, не показывая пароль, заходит по паролю один раз (встроенная программа `ssh` пароль из файла не принимает, поэтому нужна другая, например библиотека Python `paramiko`, её ставит агент), дописывает твой публичный ключ в `/root/.ssh/authorized_keys` и проверяет вход по ключу.
3. Агент удаляет файл с паролем. Проверь, что его в «Загрузках» больше нет, и смени пароль root в панели провайдера.
4. Дальше агент входит только по ключу. Не получилось или в панели нет пароля: это вопрос к поддержке провайдера. Попроси: «Добавьте публичный SSH-ключ (строка из `.pub`) в root моего сервера».

Если ключ добавлен на уже работающий сервер, в Timeweb Cloud он появляется примерно через пару минут без перезагрузки: вкладка «Доступ» → «Изменить», выбери ключ или загрузи новый.

### 6. Порты

Для Zernio и HTTPS на сервере должны быть открыты:

- 22: чтобы агент заходил по SSH;
- 80 и 443: чтобы получить сертификат HTTPS и принимать вебхуки.

Агент сам настроит файрвол на сервере. Если у провайдера есть свой файрвол в панели (в Timeweb Cloud есть раздел «Firewall»), проверь, что он эти порты не закрывает.

### 7. Адрес с HTTPS для вебхуков

Zernio хочет отправлять вебхуки на адрес с `https://`. В глоссарии Zernio сказано «HTTPS URL». Прямое правило на странице создания вебхука не прописано (в примере там `http://example.com`), но надёжнее сразу делать HTTPS.

Простыми словами: HTTPS это замочек в браузере. Для него нужно **имя**, а не просто цифры IP. Есть два пути.

**Путь А: бесплатное имя от IP (sslip.io), без покупки домена.** Сервисы sslip.io и nip.io сами превращают имя с IP в этот IP. Например, для IP 203.0.113.10 имя будет `203-0-113-10.sslip.io`. Для таких имён можно получить сертификат Let's Encrypt. Минусы: сервис держат два частных человека, сертификаты для них иногда упираются в лимиты Let's Encrypt, а годится ли сервис для постоянной работы, на их странице не написано. Для старта подходит.

**Путь Б: свой домен.** Купи домен у регистратора (например, на hoster.kz или ps.kz; на главной ps.kz цена .KZ указана 9 590 тг/год). В DNS домена добавь запись типа A на IP сервера (подробности спроси у регистратора или агента). Подожди, пока адрес «разойдётся» (бывает от минут до часов). Этот путь стабильнее.

Дальше работает программа **Caddy**. Она уже входит в шаблон ассистента, запускается вместе с ним в Docker, сама получает сертификат и принимает HTTPS. Готовый `Caddyfile` лежит в папке `assistant/`, править его не нужно. Суть настройки такая:

```
203-0-113-10.sslip.io

reverse_proxy app:8000
```

Вместо `203-0-113-10.sslip.io` будет твоё имя (агент запишет его в `.env` как `DOMAIN`), а `app:8000` это ассистент внутри Docker: он слушает порт 8000. Условия по документации Caddy:

- запись A (или AAAA) должна указывать на сервер до запуска Caddy;
- порты 80 и 443 открыты снаружи;
- сертификат Caddy берёт у Let's Encrypt, а если не вышло, у ZeroSSL;
- для самих IP-адресов и `localhost` публичный сертификат не выдаётся, нужно именно имя.

После этого адрес вебхука для Zernio выглядит так: `https://203-0-113-10.sslip.io/webhooks/zernio`.

## Куда положить ключ

Правило одно для всех сервисов. Ключ никогда не вставляй в чат с агентом.

1. Скопируй ключ из панели сервиса.
2. Открой Блокнот, вставь ключ и сохрани файл `Загрузки\<сервис>-key.txt`. Здесь `<сервис>` это короткое имя сервиса, например `zernio`.
   Имена файлов одни на весь курс: `zernio-key.txt`, `openai-key.txt`, `openrouter-key.txt`, `telegram-bot-key.txt`, `server-key.txt`, `google-sheets-key.txt`, `elevenlabs-key.txt`, `higgsfield-key.txt` (если ключ нужен).
3. Напиши агенту только это: «Ключ лежит в файле Загрузки\<сервис>-key.txt». Само значение не пиши.
4. Агент сам прочитает файл и положит значение в переменную окружения или в файл `.env` на сервере. На экране он значение не показывает.
5. После этого агент удаляет файл `Загрузки\<сервис>-key.txt`. Проверь сам, что файла в Загрузках больше нет.
6. Если ключ всё-таки попал в чат, скриншот или публичный репозиторий, сразу удали его в панели сервиса и создай новый.

Для этой инструкции файл называется `Загрузки\server-key.txt`. В нём может лежать пароль root (если не используешь SSH-ключ). IP-адрес секретом не является. Приватный SSH-ключ (файл `id_ed25519`) вообще не копируй никуда, он остаётся в папке `.ssh` на твоём компьютере.

## Частые ошибки

| Что видно | Что делать |
|---|---|
| `Permission denied (publickey)` при входе | Ключ не попал на сервер или это не тот ключ. Timeweb Cloud: добавь публичный ключ ещё раз (вкладка «Доступ» → «Изменить»), подожди пару минут. Hoster.kz и Beget: ключ добавляется агентом по паролю root (раздел 5) или через поддержку |
| `Connection timed out` | Сервер ещё создаётся, неверный IP, или порт 22 закрыт файрволом. Проверь IP и статус сервера в панели |
| Не нашёл пароль root | Timeweb Cloud: вкладки «Дашборд» или «Доступ». Не показан: сбрось на вкладке «Доступ» → «Изменить» |
| Не прошёл платёж картой | Карту другой страны принимает не каждый провайдер. Timeweb Cloud: способ «Иностранная банковская карта»; Hoster.kz: Kaspi или карта; Beget: Robokassa или тикет в поддержку |
| Сервер выключился, деньги списываются | В Timeweb Cloud списания идут и за выключенный сервер, пока он существует. Удали ненужный сервер |
| Не получается сертификат HTTPS (Caddy) | Проверь, что запись A указывает на IP сервера, порты 80 и 443 открыты и нет другого сервиса на 80. Для sslip.io возможны лимиты Let's Encrypt: подожди или купи свой домен |
| Zernio не может достучаться до адреса | Адрес должен быть с `https://`, виден из интернета, ответ `2xx` быстрее 5 секунд. См. `zernio.md` |
| Забыл, какую версию Ubuntu ставил | Агент проверит командой `lsb_release -a` на сервере |

Строки про `Connection timed out`, сертификат Caddy и версию Ubuntu описывают обычное поведение SSH и Linux. Случай с добавлением ключа и сбросом пароля в Timeweb Cloud взят из документации провайдера.
