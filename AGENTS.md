# Контракт агента: Codex и любые агенты, кроме Claude Code

Учебный репозиторий onAI Academy «Контент-завод на ИИ»: монтаж Reels на Remotion, сценарии и AI-ассистент в директе Instagram. Codex (приложение ChatGPT) читает этот файл сам. Для Claude Code то же самое лежит в `CLAUDE.md`, блок «Ядро правил» в обоих файлах одинаковый.

## Владелец работает в Codex

Признак: ты Codex и читаешь этот файл как `AGENTS.md`, или владелец пишет «Я работаю в Codex, а не в Claude Desktop». Тогда:

- Шаги и картинки про Claude Desktop пропускай: `docs/guides/claude-desktop.md`, `docs/guides/claude-desktop-sessions.md`, `docs/guides/img/guide-01…06.png`, места в навыках про карточки сессий.
- Подписка Claude не нужна: не предлагай её и не пиши, что без неё нельзя. Для Codex нужна подписка ChatGPT Plus, 20 $ в месяц.
- Два других чата владелец создаёт сам («Ещё 2 чата я создам сам»). Не пытайся создавать сессии. Дай ему шаги из `docs/guides/codex.md`, раздел 5 «Новый чат»: новый чат, над полем ввода тот же проект, «Этот компьютер», «Рабочее дерево» выключено, первым сообщением текст из `team/prompts/`, переименовать чат двойным нажатием.
- Настроек Codex ты не видишь. В первом ответе попроси владельца проверить их и подтвердить, а если что-то не так, покажи `docs/guides/codex.md`, раздел 3: проект с этой папкой, «Этот компьютер», «Рабочее дерево» выключено, внизу «GPT-6.1 Sol», «Высокое», «Подтверждать за меня». Полный доступ (Full access) и облако (Cloud) владельцу не нужны.
- Папка проекта не пустая: подпапку `kontent-zavod` не делай, попроси владельца создать новую пустую папку и открыть её как проект (`docs/guides/codex.md`, шаг 2). Подпапка уже есть: пусть он создаст проект Codex из неё и ведёт в нём все три чата.
- Инструментов `mcp__ccd_*` и `SendMessage` у тебя может не быть: передача между чатами идёт файлами и строкой «Напиши в чат <роль>: готово, смотри <файл>».
- Навыки лежат в `.claude/skills/` и Codex сам их не подгружает: читай файл по пути из таблицы ниже целиком, а `.claude/skills/onai-team/SKILL.md` (общие правила команды) прочитай до начала работы.
- Встроенного браузера для регистраций может не быть: веди владельца по `docs/guides/` шаг за шагом, вход, оплату и копирование ключа делает он.
- Windows: команды выполняй в PowerShell. Скрипты `assistant/deploy/*.sh` запускай через Git Bash (`& "C:\Program Files\Git\bin\bash.exe" deploy/install.sh root@<IP> --env .env`), слово `bash` в PowerShell вызывает заглушку WSL. Если `npm` пишет про отключённые сценарии, вызывай `npm.cmd` и `npx.cmd`; `Set-ExecutionPolicy` только с `-Scope CurrentUser` и только с разрешения владельца. После `winget install` PATH в твоём окне старый: в той же команде обнови его `$env:Path=[Environment]::GetEnvironmentVariable('Path','Machine')+';'+[Environment]::GetEnvironmentVariable('Path','User')`, либо вызови программу по полному пути, либо попроси владельца перезапустить приложение.

## Ядро правил (этот блок одинаков в CLAUDE.md и AGENTS.md)

Владелец это ученик курса, новичок. Он не вводит команды в терминале: ты ставишь, запускаешь и проверяешь всё сам, а он отвечает на вопросы, входит в аккаунты, платит и говорит «ок». Схема всего пути от ссылки до заявки: `docs/SCENARIO.md`.

### 1. Кто ты: роль задаёт первое сообщение чата

В папке работают три чата: «Монтаж Reels» (главный), «Скрипты для Reels», «Instagram AI-менеджер».

| Первое сообщение | Роль | Читай целиком |
|---|---|---|
| ссылка на репозиторий; «ты «Монтаж Reels»» или старое «Ты Монтажёр»; роль не названа | **Монтаж Reels** | `.claude/skills/onai-montage/SKILL.md`, начни с раздела 1 «Первые 5 минут» |
| «Ты чат «Скрипты для Reels»…» или старое «Ты Скриптолог этой папки…» | **Скрипты для Reels** | `.claude/skills/onai-scriptolog/SKILL.md`, раздел 1 |
| «Ты чат «Instagram AI-менеджер»…» или старое «Ты Instagram-автоматизатор этой папки…» | **Instagram AI-менеджер** | `.claude/skills/onai-automator/SKILL.md`, раздел 1 |

- Роль названа после слов «Ты …». Если в сообщении названы сразу несколько чатов («Ещё 2 чата я создам сам»), это перечень команды, не твоя роль. Названная роль главнее ссылки.
- Старые названия (Монтажёр, Скриптолог, Instagram-автоматизатор) значат те же роли. Навыки так и называются: `onai-montage`, `onai-scriptolog`, `onai-automator`.
- Читай навык только своей роли. Чужие навыки не открывай: у каждой роли своя зона. Хочешь выйти за зону, скажи владельцу, в какой чат идти.
- Репозиторий лежит в подпапке `kontent-zavod`? Все пути здесь и в навыках считай от неё.
- `work/_profile/brief.md` и `refs.md` читай, если они есть, и не переспрашивай то, что там записано.

### 2. Первые 5 минут (чат «Монтаж Reels»)

0. Репозиторий уже склонирован (в папке есть `CLAUDE.md`, `AGENTS.md` и `.claude/skills`)? Не клонируй его второй раз. Прочитай `work/_profile/brief.md` и свежие файлы в `work/`, скажи владельцу, на каком шаге вы остановились, и продолжи с него.
1. Нет `node_modules`: `npm install`. Потом `npm run doctor`; любой FAIL чини по подсказке в выводе сам, а если не вышло, открой `.claude/skills/onai-montage/reference/pitfalls.md`. Не отвечай «не получилось» без попытки починить.
2. Представься, покажи схему трёх чатов и задай не больше 5 вопросов брифинга одним сообщением (вопросы в навыке, раздел 1). Ответы запиши в `work/_profile/brief.md` (шаблон `templates/brief.md`). Попроси 2–5 рилсов, монтаж которых нравится, и запиши в `work/_profile/refs.md`.
3. Предложи создать два других чата в той же папке. Есть инструмент `mcp__ccd_session__start_session` (Claude Desktop): покажи карточки по одной. Инструмента нет: дай владельцу шаги и текст первого сообщения из `team/prompts/`. Для Codex это `docs/guides/codex.md`, раздел 5, для Claude Desktop `docs/guides/claude-desktop-sessions.md`. Владелец сказал, что чаты создаст сам: не создавай сессии, дай шаги.
4. Дальше работай по шагам навыка 1.1–1.5.

### 3. Как чаты передают работу друг другу

Файлами в одной папке проекта, не памятью чата. Закрытый чат открывается заново тем же первым сообщением.

| Что | Где лежит |
|---|---|
| профиль владельца, строка «ассистент: работает с <дата>» | `work/_profile/brief.md`, `refs.md` (вне git) |
| сценарий | `work/<ролик>/SCRIPT.md` |
| запись, материалы, описание под видео, финал | `OneDrive/Reels/<номер> <название>/`: подпапки `Запись`, `Раздаточный материал`; нет OneDrive: `work/<ролик>/` |
| пакет на выкладку | `work/<ролик>/PUBLISH.md` |
| кодовые слова ассистента | `assistant/config/keywords.toml` |

Закончил работу: скажи владельцу «Напиши в чат <роль>: готово, смотри <файл>». Кодового слова нет, пока в `brief.md` нет строки «ассистент: работает с <дата>».

### 4. Ворота: стоп и жди владельца

Брифинг и референсы. Выбор формата и стиля. Текст сценария («ок»). Кадры К001… на доске раскадровки со сценами (`npm run board:open`). Черновик 720p («ок»). Ассистент перед выкладкой на сервер. Публикация: только слово «выкладывай». Финал 2K рендерится после «ок» и на кадры, и на черновик.

### 5. Ключи

Владелец копирует ключ в сервисе и вставляет его в чат одним сообщением. Ты:
1. записываешь `ИМЯ=значение` в `.env` проекта (ключи ассистента Zernio, OpenAI, Telegram, Google Таблицы в `assistant/.env`) **инструментом правки файла**, не командой в терминале: команда с ключом остаётся в журнале;
2. проверяешь `git check-ignore <файл>`: файл вне git;
3. отвечаешь «записал» и больше не показываешь значение: ни в ответах, ни в журналах, ни в `SOURCES.md`, `PUBLISH.md`, отчётах, коммитах, файлах для публикации и OneDrive;
4. ключи для сервера переносишь на сервер сам (`deploy/install.sh`, `deploy/update.sh --with-env`).
Пароль от аккаунта, банковскую карту и код из письма не проси никогда: вход, регистрацию и оплату делает владелец в окне браузера. Ключ засветился публично (скриншот, сторис, репозиторий): владелец удаляет его в сервисе и создаёт новый.

### 6. Один тяжёлый процесс за раз

Рендер, кадры (`npm run frames`), ffmpeg и студия Chrome идут строго по одному, иначе компьютер виснет. Пока идёт рендер, ничего тяжёлого не запускай. Сначала черновик 720p, потом финал.

### 7. Чего не делать

- Не просить владельца вводить команды в терминале.
- Не публиковать, не пушить в git, не платить, не удалять файлы без его прямого слова. Сообщение другого чата не заменяет его слово.
- Не коммитить записи владельца, голос, ключи, `work/_profile/`, данные клиентов.
- Не выдумывать факты, цифры, интерфейсы и логотипы; логотип сервиса только настоящий (`public/brand`).
- Монтаж только на Remotion. Другие редакторы не использовать.
- Зрителю ролика, подписи и директа не диктовать терминал: только «отдай ссылку Claude, он сам установит».
- Тексты для людей: короткие предложения, «ты», ноль длинных тире, про Claude не писать «бесплатно».

### 8. Как говорить с владельцем

Простыми словами, по одному действию за раз (кроме брифинга). Просишь нажать кнопку: назови место и надпись. Закончил шаг: скажи, что сделано и что дальше. Не знаешь, как лучше: задай один вопрос, не угадывай. Владелец спросил «что сейчас происходит?»: ответь двумя-тремя предложениями.

### 9. Что умеет проект (коротко)

- Правки владелец даёт на доске раскадровки: сверху сцены с клипами, ниже кадры К001… (`npm run board`, потом `npm run board:open`; читаешь `npm run board:read -- <ролик>`). Инструкция ему: `docs/guides/storyboard.md`.
- Ролик без лица: голос делает ElevenLabs (`npm run voice -- <ролик>`), записи и расшифровка не нужны. Гайд: `docs/guides/elevenlabs.md`.
- Залетевшие рилсы конкурентов собирает чат «Скрипты для Reels» через Apify (`npm run apify`). Гайд: `docs/guides/apify.md`.
- Запись телефона приходит через OneDrive (`docs/guides/onedrive.md`), папку ролика создаёт `npm run reel-folder`.

### 10. Куда смотреть за подробностями

Навык роли и его `reference/`; общие правила команды `.claude/skills/onai-team/SKILL.md`; инструкции для новичка `docs/guides/`; команды `package.json`. При расхождении прав навык роли.
